# SPEC.md — Sony WF-1000XM5 Windows 控制器

版本：1.0（MVP） ｜ 状态：需求已对齐，待开发 ｜ 日期：2026-10-17

## 1. 目标

为 Windows 用户提供常驻托盘的轻量控制器，弥补 Sound Connect 不支持 Windows 的空白。MVP 范围聚焦在用户日常最常用的两项功能：**ANC 切换** 与 **电量查看**。

## 2. 范围

### 2.1 包含（MVP）

- 经典蓝牙 RFCOMM 控制通道（Sony MDR v2 协议）
- ANC 三态切换：降噪 / 通透 / 关闭
- 通透等级调节：0-20
- 通透「关注语音」开关（Sound Connect 的 Focus on Voice，协议 NCASM 帧第 6 字节）
- 电量展示：左耳 / 右耳 / 充电盒三体百分比 + 充电状态小标识
- 设备发现：枚举 Windows 已配对蓝牙设备，首次选择目标
- 系统托盘常驻 + 单击弹出小控制窗
- 耳机连接事件驱动自动建立控制通道，断开时静默退避重试
- 状态保持：通知驱动为主 + 窗口打开时全量拉取 + 低频兜底刷新（15 秒）

### 2.2 不包含（明确排除）

- 音量控制——用户确认媒体音量由 Windows 系统调节控制耳机即可，语音提示音量（-2~+2 五档）也不需要
- EQ / DSEE / Speak-to-Chat / 触控手势 / 多点控制等 Sound Connect 高级功能
- 多设备管理——单台目标耳机
- 开机自启动——稳定后再加（不在 MVP 验收范围）
- BLE GATT 通道——MVP 仅走 RFCOMM（更成熟、有先例），BLE 留作后续扩展

## 3. 技术方案

| 项 | 决策 |
|---|---|
| 语言/框架 | C# / .NET 10 / WPF |
| 蓝牙 API | `ws2_32.dll` P/Invoke：`socket(AF_BTH, SOCK_STREAM, BTHPROTO_RFCOMM)` + `SOCKADDR_BTH` 填 v2 SDP UUID |

## 4. 功能规格

### 4.1 ANC 控制

**协议命令**：`NCASM_SET_PARAM (0x68)`，InquiredType = `NC_MODE_SWITCH_AND_ASM_SEAMLESS (0x14)`

**完整 7 字节载荷**：`68 14 01 <开关> <NcValue> <AmbientSoundMode> <等级>`

| UI 操作 | 映射字节 |
|---|---|
| 切到降噪 | `开关=01 NcValue=01(单)` 或 `02(双)` AmbientSoundMode=00 等级=任意(降噪时忽略) |
| 切到通透 | `开关=01 NcValue=00 AmbientSoundMode=00 等级=<0-20>` |
| 切到关闭 | `开关=00 NcValue=00 AmbientSoundMode=00 等级=00` |

字段说明：
- NcValue：0=OFF, 1=NC单, 2=NC双, 3=AUTO, 4=AUTO单, 5=AUTO双 — MVP 只用 0/1，AUTO 等留扩展
- AmbientSoundMode：0=普通, 1=人声 — 面板以「关注语音」开关暴露（仅通透模式可调；实际字节布局见 PROTOCOL_NOTES §3.3，InquiredType 已改用真机验证的 0x17）
- 等级：0-20，仅在通透模式下生效，UI 滑条范围映射

**状态回读**：连接后通过 `NCASM_RET_PARAM (0x67)` / `NCASM_NTFY_PARAM (0x69)` 同布局解析；耳机端（手机 Sound Connect）改动会通过 NTFY 自动推送。

### 4.2 电量展示

**协议命令**：`POWER_GET_STATUS (0x22)`

| 查询 | payload | 回复 |
|---|---|---|
| 左右耳 | `22 01` | `23 01 <L:1> <L充电:1> <R:1> <R充电:1>` |
| 充电盒 | `22 02` | `23 02 <盒:1> <盒充电:1>` |

电量等级 0-100。充电状态字节：0=未充电, 1=充电中, 3=已充满, 2=未知。

**主动推送**：`POWER_NTFY_STATUS (0x25)` — 电量变化时耳机自动推送，无需轮询。

**UI 展示**：三体百分比数字 + 充电状态小标识（充电中/已充满/在盒），不暴露原始字节。

### 4.3 连接生命周期

**首次运行**：
1. 枚举 Windows 已配对蓝牙设备，过滤为音频类
2. 用户选择目标耳机，记录 MAC 地址到本地配置
3. 之后全自动

**自动连接**（事件驱动）：
1. 注册 `RegisterDeviceNotification` 监听蓝牙设备 arrival
2. 监听到目标耳机连上 Windows（音频通道建立）→ 立即建 RFCOMM 控制通道
3. 控制通道建立后发 INIT（`00 00`）确认 v2 设备，再拉取全量状态
4. 监听到耳机断开 → 释放控制通道资源

**连接前置条件（不抢连）**：任何 RFCOMM `connect()` 之前必须确认 Windows 配对表里目标
处于已连接状态（OS 已持有链路）。OS 报告未连接时**绝不发起连接**——对不在电脑旁的耳机
发 connect 会在空中 page 它，可能把正连着手机等其它主机的耳机抢走。30 秒兜底轮询只读
本地配对表（无无线电活动），仅用于补漏 arrival 事件。

**失败处理**：
- 控制通道连接失败：静默退避重试（间隔 1s → 5s → 30s，封顶 30s）
- 重试期间若 OS 报告目标已不在连（removal 事件或重连 tick 检查）→ 落回"未连接"，
  停止重试；不再出现永远停在"重连中"的状态
- 托盘图标状态反映连接（已连接 / 重连中 / 未连接）
- 不打扰用户，不弹通知

### 4.4 状态同步策略

主路径：耳机主动 NTFY 通知（电量变化、ANC 改动都会推）

兜底：
- 控制窗打开时全量拉取一次（保证打开瞬间数据新鲜）
- 每 15 秒低频兜底刷新（应对 NTFY 偶发丢失，以及设备不推送的状态——例如耳机放回
  充电盒：协议没有"入盒"通知，只能靠轮询发现。2026-10 由 2 分钟缩短至 15 秒）
- 所有命令经同一串行闸门排队（协议同一时刻只允许一条在途），兜底刷新与用户操作互不冲突

跨端一致性保障：用户手机 Sound Connect 改 ANC → 耳机推 NTFY → 本应用 UI 自动更新。这是 NTFY 路径的核心价值，必须正确处理。

### 4.5 命令失败防护

每次命令发送：
1. 发送后等待 ACK（按序列号匹配）
2. 收到 RET 帧时校验 sum8、长度、命令码、子类型
3. 校验失败或超时（默认 3 秒）→ 重试一次
4. 两次失败 → UI 显示"耳机无响应"，不自动猜测性重发

绝不发送未经用户操作的命令，避免 UI 与耳机实际状态长期不一致。

## 5. UI 规格

### 5.1 托盘图标

- 双状态图标：已连接（彩色耳机）/ 未连接或重连中（灰色）
- 右键菜单：打开控制窗 / 退出
- 左键单击：切换控制窗显隐

### 5.2 小控制窗

布局（垂直）：

```
┌──────────────────────────┐
│  Sony WF-1000XM5         │
│  ─────────────────────   │
│  电量                     │
│    左耳  ▓▓▓▓░  80%       │
│    右耳  ▓▓▓░░  60% 充电中 │
│    充电盒 ▓▓▓▓▓ 100%      │
│  ─────────────────────   │
│  ANC                      │
│   [降噪] [通透] [关闭]   │
```

- 窗口失去焦点自动隐藏（仿 Windows 音量弹窗行为）
- 等级滑条仅在通透模式下可调，降噪/关闭时禁用
- 面板卡片：圆角 16、毛玻璃背景——分层窗口拿不到 DWM 系统模糊，采用快照方案：每次打开前截取卡片身后的屏幕区域，C# 分离式盒模糊（≈高斯）+ 按快照平均亮度自适应提白（暗壁纸多提、亮壁纸少提，底色恒定锚定在适合灰色标签文字的亮度带），提白烘焙进不透明画笔（alpha<1 会把暗色原始像素混回来抵消提白）；截屏/模糊失败时回退 XAML 静态底色，失败记录 diag 日志
- 面板顶部展示官方产品图（按设备颜色动态选择），图片上下边距与卡片内容区隔开

### 5.3 首次设备选择窗

- 列表展示 Windows 已配对的蓝牙音频设备（名称 + MAC）
- 选中后保存配置，重启时跳过

## 6. 验收标准（三级）

### L1 — 硬门槛（必须达到才考虑继续）

- [ ] 应用启动后能枚举已配对蓝牙设备
- [ ] 选择 WF-1000XM5 后建立 RFCOMM 控制通道
- [ ] 发送 INIT (`00 00`) 收到 8 字节 v2 回复
- [ ] 发送电量查询 (`22 01` + `22 02`)，解析出左右耳和充电盒三体百分比，与耳机语音播报一致

### L2 — 完整验收

- [ ] ANC 三态切换生效，耳朵能听出降噪/通透/关闭变化
- [ ] 通透等级滑条 0-20 实时生效
- [ ] 手机 Sound Connect 改 ANC 后，电脑端 UI 在数秒内自动更新（NTFY 路径）
- [ ] 手机改 ANC 后即使错过 NTFY，15 秒兜底刷新也能追上
- [ ] 电量百分比和充电状态正确展示
- [ ] 命令失败时不卡死、不乱发，UI 提示"耳机无响应"

### L3 — 发布标准

- [ ] 托盘常驻一周日常使用稳定
- [ ] 耳机连接/断开事件驱动自动建连/释放
- [ ] 重连退避策略有效，不刷屏不卡死
- [ ] 无内存泄漏（长时间常驻）

## 7. 已知风险与缓解

| 风险 | 缓解 |
|---|---|
| Windows 已通过 A2DP 占着耳机时控制通道偶发 ACK 超时（社区 issue #26） | 重连时按 SDP 重新发现服务；首次连接失败重试一次 |
| 固件版本差异（测试样本 6.1.0，用户固件可能更新） | 命令字节布局来自 v13.3.0 APK 一手证据，覆盖最新协议；遇到不对的响应字节再比对 |
| RFCOMM 通道被其它 Sony 控制软件占用 | 检测占用并提示用户关闭 |
| Windows 蓝牙栈偶发不报 arrival 事件 | 未连接态 30 秒定时探测配对表作为事件兜底 |

## 8. 实施顺序

每步独立可验证，按 L1 → L2 → L3 验收节奏推进：

| 步骤 | 交付 | 验证 |
|---|---|---|
| 1 | 控制台原型：socket 连接 + INIT + 读电量 | L1 全部 |
| 2 | 控制台：ANC 读取 + 三态切换 + 等级调节 | L2 部分 |
| 3 | 控制台：NTFY 接收 + 状态被动更新 | L2 跨端同步 |
| 4 | WPF 壳：托盘 + 小控制窗 + 首次设备选择 | UI 体验 |
| 5 | 事件驱动连接 + 退避重试 + 兜底刷新 | L3 发布 |

第 1 步是关键里程碑——电量读出即证明整条链路（socket、SDP、封帧、v2 命令）打通。

## 10. 决策记录（Grilling 对齐结果）

| 决策点 | 选择 | 备注 |
|---|---|---|
| 音量控制 | 不做 | 媒体音量走 Windows 系统，语音提示音量用户不需要 |
| ANC 粒度 | 三态 + 等级滑条 | 协议 7 字节命令完整支持；AUTO/人声模式留扩展不暴露 |
| 电量展示 | 百分比 + 充电小标识 | 充电状态是电量回复帧免费带的字段，零协议成本 |
| 应用形态 | 托盘常驻 | 核心体验 |
| 自动连接 | 事件驱动 | 监听耳机 arrival 自动建控制通道 |
| UI 形态 | 小控制窗 | 仿 Windows 音量弹窗，失焦自动隐藏 |
| 设备发现 | 已配对列表选择 | 首次选一次，之后全自动 |
| 多设备 | 不支持 | 单台目标耳机，符合实际场景 |
| 失败处理 | 静默退避重试 | 1s → 5s → 30s 封顶 |

| 验收标准 | 三级 | L1 硬门槛 / L2 完整 / L3 发布 |
